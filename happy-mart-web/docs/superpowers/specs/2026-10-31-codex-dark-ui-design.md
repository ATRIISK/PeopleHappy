# Codex 风格深色 UI 改造设计

日期：2026-10-31
状态：已确认范围 A1，待实现
范围：`E:\PeopleHappy\happy-mart-web`

## 1. 目标

把现有“暖橙市集”视觉统一改为 Codex 工作台风格的全站深色界面，并增加克制的动态反馈。改造需要覆盖前台、后台和 Element Plus 组件，但不得修改接口、Pinia 状态、路由或后端逻辑。

成功标准是打开页面后能明显看出统一、现代、偏工具感的 Codex 气质，同时商品图、价格、订单状态和表单仍然清晰可读。仅构建通过不算完成，还必须完成桌面与移动端实拍检查。

## 2. 视觉语言

### 2.1 配色

| 用途 | 色值 |
|---|---|
| 页面底色 | `#0B0D10` |
| 基础表面 | `#111318` |
| 浮层表面 | `#171A20` |
| 高亮表面 | `#1D2129` |
| 描边 | `#282D35` |
| 强描边 | `#3A414D` |
| 主文字 | `#F2F4F7` |
| 次文字 | `#AAB2BF` |
| 弱文字 | `#737D8C` |
| 主强调色 | `#8BE9B0` |
| 强调悬停色 | `#5DD79A` |
| 冷色辅助 | `#6DC8E8` |
| 警告色 | `#F0B86E` |
| 危险色 | `#FF6B6B` |

页面不使用纯黑。主背景、卡片和弹层至少保持三个明度层级。薄荷绿只用于交互、状态和焦点，不大面积铺满页面。价格使用浅色强文字，促销和危险信息使用独立暖色，避免与绿色状态混淆。

### 2.2 形状和层级

- 卡片使用 10 至 16 像素圆角，边框优先于重阴影。
- 顶栏使用半透明深色毛玻璃和底部细线。
- 首页 Hero 使用石墨层、细网格、低强度薄荷绿环境光和一个终端式状态标签。
- 商品图保持原始亮度，卡片内容区使用深色表面。
- 后台侧栏比内容区更暗，选中菜单使用薄荷绿细条和柔和背景。
- Element Plus 的输入框、下拉框、表格、分页、弹窗、日期选择器同步深色变量。

## 3. 动效系统

| 场景 | 动效 |
|---|---|
| 页面和区块进入 | 460 至 600 毫秒淡入，上移 10 至 16 像素 |
| 商品卡片出现 | 按顺序错峰 40 至 60 毫秒 |
| 卡片悬停 | 上移 4 像素，绿色边框和柔光 |
| 按钮悬停 | 扫光从左侧掠过，文字和边框提亮 |
| 搜索框聚焦 | 薄荷绿描边和低强度呼吸光 |
| Hero 状态标签 | 终端光标缓慢闪烁 |
| 加载状态 | 低对比脉冲，不使用旋转大图标 |
| 页面切换 | 使用轻量透明度过渡 |

所有动效只改变视觉属性。连续动画必须低幅度，不闪烁。通过 `prefers-reduced-motion: reduce` 关闭位移、扫光和闪烁，只保留必要的即时状态变化。

## 5. 兼容与可访问性

- 主文字与背景对比度不低于 7:1，次文字不低于 4.5:1。
- 键盘焦点必须有清晰可见的薄荷绿外框。
- 图片、状态、价格和禁止操作不能只靠颜色区分。
- 390 像素视口下不能出现横向溢出。
- 动画不得影响滚动和点击命中。
- Element Plus 弹层的遮罩、文字、边框和禁用态必须可辨认。

## 6. 验收

1. 运行 `npm run build`，退出码为 0。
2. 在桌面视口检查首页、商品列表、商品详情、购物车、登录、注册、订单列表和后台仪表盘。
3. 在 390 像素宽视口检查首页、商品列表、商品详情、购物车和后台仪表盘。
4. 页面 `scrollWidth` 不得超过 `innerWidth`。
5. 检查搜索聚焦、卡片悬停、页面进入、AI 助手和加载状态。
6. 确认没有新增接口请求、业务状态变化或后端改动。

## 7. 风险控制

- 旧页面存在浅色硬编码，不能只改设计令牌。实施时用颜色扫描逐项替换高频页面中的固定浅色和暖橙色阴影。
- 深色页面容易出现层级糊在一起，必须同时检查边框、背景和文字的三层对比。
- 动效过多会降低工具感，因此只保留进入、悬停、焦点、加载四类反馈。
- 现有 `dist` 是旧构建产物，验收必须基于新构建，不能直接观察旧 `dist`。
