# 宝塔面板部署详细操作（2核2G · happy-mart.pw）

> 全程在宝塔面板里点，只有 3 处需要敲命令（都在面板自带的终端里敲）。
> 版本参考：宝塔 Linux 面板 9.x。7.x / 8.x 菜单略有差异，文中会标出来。

---

## 阶段零：进面板前先做三件事

这三件事不做，后面全是坑。

### 0.1 阿里云安全组

阿里云控制台 → 云服务器 → 你的实例 → 安全组 → 配置规则 → 入方向，手动添加：

| 端口范围 | 授权对象 | 用途 |
|---|---|---|
| 22/22 | 你的本机公网 IP | SSH（别填 0.0.0.0/0） |
| 80/80 | 0.0.0.0/0 | 网站 |
| 8888/8888 | 你的本机公网 IP | 宝塔面板 |

3306、6379、5672、15672 **一律不放行**，compose 里已经把它们绑在 `127.0.0.1`，公网本来就够不着。

### 0.2 加 2G swap

宝塔面板里也能加，但用命令行最快。SSH 或面板终端里执行：

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf && sudo sysctl -p
free -h
```

最后一行看到 `Swap: 2.0Gi` 才算成功。**2G 内存跑 MySQL+RabbitMQ+JVM，没 swap 迟早被 OOM Killer 杀进程。**

### 0.3 确认 MySQL 容器能拿到 3306

如果你之前在宝塔里装过 MySQL，先去「软件商店 → 已安装」把它停掉或卸载，否则 3306 被占，容器起不来。

## 阶段一：面板初始化

### 1.1 登录面板

浏览器打开 `http://你的公网IP:8888`，输账号密码。

如果是阿里云镜像自带的宝塔，初始密码在服务器上执行 `bt default` 能看到（面板 → 终端里也能跑）。

### 1.2 ★ 关掉推荐套件安装（最关键的一步）

登录后宝塔会弹一个「推荐安装套件」的窗口，**默认勾选了 LNMP（Nginx + MySQL + PHP + phpMyAdmin）**。

**点「关闭」或「自定义」，什么都不要装。**

点了一键安装的后果：MySQL 吃掉 400MB+ 内存并抢占 3306，PHP-FPM 再吃 100MB，你的 2G 直接见底，Docker 里的容器全部起不来，而且排查时会很懵。

### 1.3 软件商店只装两个

左侧菜单 → **软件商店** → 搜索并安装：

| 软件 | 作用 | 备注 |
|---|---|---|
| **Nginx** 1.24 或 1.26 | 托管前端 + 反代后端 | 编译安装或极速安装都行，极速快 |
| **Docker** 管理器 | 管容器 | **9.x 面板左侧菜单直接有 Docker，不用装插件**；7.x/8.x 去软件商店搜"Docker管理器"装 |

装完等进度条走完。Nginx 一般 2-5 分钟。

### 1.4 配 Docker 镜像加速（不做会卡死在拉镜像）

左侧 → **Docker** → 右上角「设置」（或"配置"）→ 镜像加速，填入你的阿里云加速地址：

```
# 阿里云 → 容器镜像服务 → 镜像工具 → 镜像加速器，复制专属地址
https://xxxxxxxx.mirror.aliyuncs.com
```

保存后 Docker 会自动重启。

**为什么必须做**：国内直连 Docker Hub 拉 `mysql:8.0`（800MB+）经常几分钟没进度甚至超时，容器起不来你会以为是配置错了。

### 1.5 关掉用不上的常驻服务

面板 → 设置 → 面板设置，可以关掉：
- 网站防篡改
- 文件监控
- 监控里的高频采集

2G 内存每一百兆都值钱。

## 阶段二：上传项目

### 2.1 上传压缩包

左侧 → **文件** → 进入 `/www/wwwroot` → 点「上传」→ 选本地 `happy-mart-deploy.tar.gz`（92MB）。

上传窗口会显示进度，92MB 大概 1-3 分钟（看你的上行带宽）。

> 如果面板上传卡住或失败，用面板终端走 scp 更稳：
> ```bash
> cd /www/wwwroot
> # 在你的 Windows 本机执行（Git Bash）：
> # scp happy-mart-deploy.tar.gz root@公网IP:/www/wwwroot/
> ```

### 2.2 解压到独立目录

在文件管理器里右键 `happy-mart-deploy.tar.gz` → **解压** → 解压到 `/www/wwwroot/happy-mart`（手动改一下路径，别解压到当前目录，否则文件会散在 wwwroot 里）。

解压完进 `/www/wwwroot/happy-mart`，应该看到：

```
backend/        docker-compose.yml    nginx/
data/           .env.example          sql/
DEPLOY.md       dist/                 sql-optional/
```

⚠️ **`.env.example` 是隐藏文件（点开头）**，文件管理器右上角「设置」里勾上「显示隐藏文件」才看得见。看不到它你后面没法复制。

### 2.3 建三个运行时目录

继续在文件管理器里，`/www/wwwroot/happy-mart` 下新建三个目录：

```
data/mysql      ← MySQL 数据（首次启动自动初始化）
data/upload     ← 商品图片（包里已有 200 张演示图）
data/kb         ← AI 知识库索引（自动生成）
logs            ← 后端日志和 OOM dump
```

`data/upload` 包里自带了，另三个需要手动建。**不建的话 Docker 会用 root 自动创建，权限是对的，但你先建好更清楚发生了什么。**

## 阶段三：配 .env

### 3.1 复制一份

文件管理器里，右键 `.env.example` → **复制** → 粘贴 → 重命名为 `.env`。

（或者终端里 `cp .env.example .env`，更快。）

### 3.2 生成三个密码

左侧 → **终端**（9.x 在左侧菜单；没有的话点右上角的 `>_` 图标）→ 连上服务器后敲：

```bash
openssl rand -base64 24   # 记下来，当 MySQL 密码
openssl rand -base64 24   # 记下来，当 RabbitMQ 密码
openssl rand -base64 32   # 记下来，当 JWT_SECRET
```

跑三次，三个不同的值。

### 3.3 编辑 .env

文件管理器里右键 `.env` → **编辑**，改成这样：

```ini
MYSQL_ROOT_PASSWORD=第一个密码
RABBITMQ_USER=hm_admin
RABBITMQ_PASSWORD=第二个密码
ALIPAY_NOTIFY_URL=http://公网IP/api/pay/notify
JWT_SECRET=第三个密码
# GLM_API_KEY 用不到就整行注释掉，别留 "GLM_API_KEY=" 空值
```

保存（Ctrl+S 或右上角保存按钮）。

**两个必须注意的点**：

1. `ALIPAY_NOTIFY_URL` 现在填**公网 IP**，备案下来后再改成 `http://happy-mart.pw/api/pay/notify`。
2. `MYSQL_ROOT_PASSWORD` **一旦容器启动就固化在数据卷里**，之后改 `.env` 不生效。所以这一步必须一次填对，填错了要删 `data/mysql` 重来。

## 阶段四：启动容器

### 4.1 在终端里启动

面板 → 终端：

```bash
cd /www/wwwroot/happy-mart
docker compose up -d
```

第一次要拉 4 个镜像（mysql 800MB、rabbitmq 200MB、redis 30MB、jre 180MB），配了加速器大约 3-8 分钟。

看到四个容器都是 `Started` / `Running` 就 OK。

> **不用面板的 Compose 界面**：宝塔不同版本的 Compose 模板功能位置和字段都不一样，容易填错。终端里一条命令最可靠，而且面板的 Docker 页能看到同样的容器状态。

### 4.2 在面板里看状态

左侧 → **Docker** → 容器，应该看到 4 个：

| 容器名 | 状态 | 说明 |
|---|---|---|
| `hm-mysql` | 运行中 / healthy | 首次要初始化数据库，约 1-2 分钟 |
| `hm-redis` | 运行中 / healthy | 秒起 |
| `hm-rabbitmq` | 运行中 / healthy | 约 30-40 秒 |
| `hm-backend` | 运行中 | 等前三个 healthy 后才启动 |

点容器名 → 日志，可以实时看输出。

**如果 `hm-mysql` 一直重启**：内存不够或密码不对，看日志最后几行。
**如果 `hm-backend` 一直重启**：点日志往上翻，通常是连不上 MySQL（还没初始化完）或 RabbitMQ 认证失败。

### 4.3 验证数据库初始化

终端里：

```bash
docker exec -it hm-mysql mysql -uroot -p -e "USE happy_mart; SHOW TABLES; SELECT COUNT(*) FROM product;"
```

输入你 `.env` 里设的 MySQL 密码。

预期输出：8 张表 + `12`（商品数）。

**如果表是空的**：说明初始化脚本没跑。原因是 `data/mysql` 目录在启动前已经有内容了（Docker 只在数据目录为空时执行初始化）。清掉重来：

```bash
cd /www/wwwroot/happy-mart
docker compose down
rm -rf data/mysql
docker compose up -d
```

### 4.4 验证后端

```bash
curl -s http://127.0.0.1:8074/api/category/tree | head -c 200
```

返回 JSON 且带分类名，就说明后端通了。

## 阶段五：建站

### 5.1 添加站点

左侧 → **网站** → 「添加站点」：

| 字段 | 填什么 |
|---|---|
| 域名 | `happy-mart.pw`（宝塔会自动加 `www.happy-mart.pw`）<br>**备案没下来前先填公网 IP** |
| 根目录 | `/www/wwwroot/happy-mart/dist` |
| FTP | 不创建 |
| 数据库 | 不创建（MySQL 在 Docker 里） |
| PHP 版本 | **纯静态** |

点提交。

### 5.2 确认根目录

建完站后点站点名 → 弹出设置窗口 → 左侧「网站目录」→ 确认根目录是 `/www/wwwroot/happy-mart/dist`，运行目录留空，**不要勾"防跨站攻击(open_basedir)"**（这是 PHP 的机制，纯静态站点勾了反而可能干扰读文件）。

### 5.3 改 Nginx 配置

还是站点设置窗口 → 左侧「**配置文件**」→ 右侧是编辑器，把整个 `server { }` 块替换成 `deploy/nginx/baota-site.conf` 里的内容。

配置文件路径：`/www/server/panel/vhost/nginx/happy-mart.pw.conf`

**三段核心，缺一不可**：

```nginx
# ① SPA 路由：不加的话刷新 /admin/order 这类页面直接 404
location / {
    try_files $uri $uri/ /index.html;
}

# ② 上传大小：宝塔默认 1m，不调大传 1MB 以上的商品图报 413
client_max_body_size 5m;

# ③ ^~ 前缀：不加的话 /upload/xxx.jpg 会被静态资源正则抢走，
#    然后去 dist 目录找文件 → 全 404
location ^~ /upload/ {
    proxy_pass http://127.0.0.1:8074;
    ...
}
```

复制粘贴时注意把整段 `server { ... }` 替换掉，别只贴里面几行导致花括号不配对。

### 5.4 保存并重载

编辑器右上角「保存」。宝塔会提示"配置已修改，是否重载"→ 点是。

如果没提示，终端里：

```bash
nginx -t && nginx -s reload
```

`nginx -t` 报 `syntax error` 就是上面粘贴时括号没配对，回去检查。

## 阶段六：验收

浏览器打开：

| # | 打开什么 | 应该看到 |
|---|---|---|
| 1 | `http://公网IP/` | 商城首页，商品卡片成排 |
| 2 | 商品详情，然后按 F5 刷新 | 页面正常，不出现 404 |
| 3 | 注册一个账号 → 登录 | 顶栏显示用户名 |
| 4 | 加购物车 → 下单 | 订单创建成功，库存数减 1 |
| 5 | 进入支付页 | 出现支付宝二维码 |
| 6 | 手机支付宝扫一扫（沙箱版 App） | 付款后订单变「已支付」 |

### 开管理员账号

先在首页注册一个账号，然后终端里提权：

```bash
docker exec -it hm-mysql mysql -uroot -p -e "USE happy_mart; UPDATE \`user\` SET role='ADMIN' WHERE username='你的账号';"
```

退出重新登录，就能进 `/admin`。

### 商品图如果全是空白

初始化数据里的图片是 `picsum.photos` 外链，国内访问经常超时。换成本地图：

```bash
cd /www/wwwroot/happy-mart
docker exec -i hm-mysql mysql -uroot -p happy_mart < sql-optional/03-local-images.sql
docker exec hm-redis redis-cli FLUSHDB
```

刷新页面，图片就变成站内 `/upload/20260815/prodX.jpg` 了。

## 阶段七：日常维护（面板操作）

### 看容器状态

左侧 → Docker → 容器。四个都在「运行中」就正常。

点容器 → 「日志」看实时输出，「终端」可以直接进容器内部。

### 重启后端（改了 jar 之后）

文件管理器上传新的 `app.jar` 覆盖 `/www/wwwroot/happy-mart/backend/app.jar`，然后：

Docker → 容器 → `hm-backend` → 右侧「重启」。

### 备份数据库

左侧 → **计划任务** → 添加任务：

| 字段 | 填什么 |
|---|---|
| 任务类型 | Shell 脚本 |
| 任务名称 | 备份 happy_mart |
| 执行周期 | 每天 3 点 |
| 脚本内容 | 见下 |

```bash
docker exec hm-mysql mysqldump -uroot -p你的密码 happy_mart | gzip > /www/backup/happy_mart_$(date +\%F).sql.gz
find /www/backup -name "happy_mart_*.sql.gz" -mtime +7 -delete
```

（`\%F` 里的反斜杠不能少，宝塔的计划任务会转义 `%`。）

### 面板里看内存

左侧 → 首页，顶部有实时内存/CPU 曲线。**内存长期贴顶就说明 2G 到极限了**，考虑升配。

也可以 Docker → 容器，每个容器右侧显示 CPU 和内存占用。

## 面板部署最容易踩的五个坑

| 坑 | 后果 | 怎么避开 |
|---|---|---|
| 首次登录点了一键安装 LNMP | MySQL/PHP 抢端口吃内存，容器全起不来 | 阶段 1.2，点关闭 |
| `.env` 里 MySQL 密码填错 | 容器起来但后端连不上，一直重启 | 填完核对一遍；错了删 `data/mysql` 重来 |
| `data/mysql` 目录事先有内容 | SQL 初始化脚本不执行，库里没表 | 启动前确保该目录为空或不存在 |
| 忘了配 Docker 镜像加速 | 拉镜像卡住，以为容器启动失败 | 阶段 1.4 |
| Nginx 配置只贴了 location 没替换整个 server 块 | `nginx -t` 报花括号不配对 | 整段替换，保存后看是否提示重载 |

## 阶段八：开启自动更新部署（可选，2026-11-05 起）

不想每次手动传 `dist.zip` / `app.jar`，可以挂上自动部署：

```
本地 bash deploy/release.sh → Gitee Release → 宝塔「计划任务」每 10 分钟轮询 → 自动原子切换 + 健康检查 + 失败回滚
```

三步：

1. 把 `deploy/update.sh` 和 `deploy/update.conf` 传到服务器 `/www/wwwroot/happy-mart/deploy/`
2. 宝塔「**计划任务**」→ 添加任务 → 类型选 **Shell 脚本** → 周期选 **每 10 分钟** → 脚本内容填
   `bash /www/wwwroot/happy-mart/deploy/update.sh 2>&1 | tee -a /www/wwwlogs/hm-deploy.log`
3. 本地准备 Gitee 私人令牌（`projects` 权限）后 `export GITEE_TOKEN=xxx`，再 `bash deploy/release.sh`

完整步骤、故障排查表、命令速查见 **`deploy/AUTO-DEPLOY.md`**。
