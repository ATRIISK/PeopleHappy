# 自动部署上手清单（照着做，勾选）

> 目标：把"本地构建 → Gitee Release → 宝塔计划任务自动部署"这条链路第一次跑通。
> 全程约 30 分钟，其中只有两个地方要等（本地构建 3~5 分钟、服务器轮询最多 10 分钟）。
> 跑通之后，以后每次发版只要一条命令 + 最多等 10 分钟。

## 总览（5 步）

```
① 生成 Gitee 令牌        本地浏览器   3 分钟
② 配 git 推送凭据        本地终端     2 分钟
③ 传脚本到服务器          宝塔面板     5 分钟
④ 加宝塔计划任务          宝塔面板     3 分钟
⑤ 跑第一次发布            本地终端     等 10 分钟
```

---

## ① 生成 Gitee 私人令牌（本地浏览器）

**在哪点**：浏览器打开 https://gitee.com → 右上角**头像** → **设置** → 左侧**安全设置** → **私人令牌** → 点**生成新令牌**

**填什么**：

| 字段 | 填 |
|---|---|
| 私人令牌描述 | `happy-mart-deploy`（随便写） |
| 权限 | **只勾 `projects`**（仓库读写权限就够，别多勾） |

点生成 → **输入 Gitee 登录密码验证** → 复制那串 token（**只显示这一次**，关掉就看不到了）。

**看到什么算成功**：一串 40 位左右的随机字符串，已经复制到剪贴板。

**放哪**：存到密码管理器或者先粘到记事本。下一步要用。

---

## ② 配 git 推送凭据（本地 Git Bash）

**为什么要配**：`release.sh` 要把 `deploy/manifest.txt` 推到 Gitee，服务器是从 Gitee 拉这个文件的。不配凭据的话推送会卡在要密码。

**做法**：在 **Git Bash**（不是 cmd、不是 PowerShell）里执行：

```bash
cd /e/PeopleHappy
git push origin master
```

第一次会弹一个 Windows 凭据窗口：

| 框 | 填 |
|---|---|
| 用户名 | `liao-zhenhan` |
| 密码 | **粘贴第 ① 步的私人令牌**（不是你的登录密码） |

> Gitee 开了双因素认证后，HTTP 推送的密码位置必须填私人令牌。如果报 `Authentication failed`，就是这里填错了。

**看到什么算成功**：输出 `master -> master` 或 `Everything up-to-date`。

---

## ③ 传脚本到服务器（宝塔面板）

**在哪点**：宝塔面板 → 左侧**文件**

1. 顶部路径框输入 `/www/wwwroot/happy-mart` → 回车
2. 点「**新建目录**」，名字填 `deploy` → 确认
3. 进入 `deploy` 目录 → 点「**上传**」→ 把本地这两个文件拖进去：
   - `E:\PeopleHappy\deploy\update.sh`
   - `E:\PeopleHappy\deploy\update.conf`
4. 上传完，在列表里点 `update.conf` 右键 → **编辑**，把这一行：

   ```
   HEALTH_URL=http://127.0.0.1:8074/api/health
   ```

   改成：

   ```
   HEALTH_URL=http://127.0.0.1:8074/api/product/list
   ```

   > **为什么第一次先用 `/api/product/list`**：`/api/health` 是跟着新 jar 一起上线的，服务器现在跑的还是旧 jar，那个接口还不存在。第一次自动部署如果去打 `/api/health` 会拿到 404，脚本会判定"服务不健康"→ 自动回滚 → 新版永远发不上去。用旧 jar 就有的业务接口先顶上，等新 jar 部署成功后（第 ⑤ 步末尾）再改回来。

5. 改完点保存。

**看到什么算成功**：文件列表里有 `update.sh` 和 `update.conf` 两个文件。

**如果上传后不放心换行符**：宝塔面板 → 左侧**终端**，执行

```bash
file /www/wwwroot/happy-mart/deploy/update.sh
```

输出里**不含 `CRLF`** 就是对的（应该是 `ASCII text`）。如果含 CRLF，执行：

```bash
sed -i 's/\r$//' /www/wwwroot/happy-mart/deploy/update.sh /www/wwwroot/happy-mart/deploy/update.conf
```

## ④ 加宝塔计划任务（宝塔面板）

**在哪点**：宝塔面板 → 左侧**计划任务** → 点「**添加任务**」

**填什么**：

| 表单项 | 填 |
|---|---|
| 任务类型 | **Shell 脚本** |
| 任务名称 | `众乐商城自动部署` |
| 执行周期 | **N 分钟** → 填 `10` |
| 脚本内容 | `bash /www/wwwroot/happy-mart/deploy/update.sh >> /www/wwwlogs/hm-deploy.log 2>&1` |

点「提交」。

**立刻验证脚本能跑**：在任务列表里点这条任务右边的「**执行**」按钮，然后点「**日志**」看输出。

**看到什么算成功**：日志里出现

```
[xx:xx:xx] [INFO] ===== 自动部署开始 (mode=deploy) =====
[xx:xx:xx] [ERROR] 版本清单缺少 version/tag 字段，放弃部署
```

> **那个 ERROR 是正常的**。因为 `deploy/manifest.txt` 现在还是空的（还没发过版），脚本拉不到版本号就停下了。**这说明脚本本身跑通了、网络也通**。真正部署会在第 ⑤ 步之后自动进行。

如果这里报的是别的错（比如「缺少依赖命令」），把错误贴给我。

## ⑤ 跑第一次发布（本地 Git Bash）

**在 Git Bash 里**执行：

```bash
cd /e/PeopleHappy
export GITEE_TOKEN=第①步复制的令牌
bash deploy/release.sh
```

**它会依次做**（整个过程 3~8 分钟）：

| 步骤 | 你会看到 |
|---|---|
| 构建前端 | `npm run build` 的输出 |
| 构建后端 | `mvnw package` 的输出（很安静，因为加了 `-q`） |
| 打包 | `打包前端产物 → dist-20261105-xxxxxx.zip` |
| 写清单 | `版本清单已写入 deploy/manifest.txt` |
| 推 git | `chore(release): v20261105-xxxxxx` |
| 建 Release | `Release 创建成功 id=xxxxx` |
| 传产物 | `上传资产 dist-xxx.zip` / `上传资产 app-xxx.jar` |
| 完成 | `===== 发布完成 =====` |

**看到什么算成功**：最后一行是 `===== 发布完成 =====`，并且终端提示「服务器端最多 10 分钟内自动部署」。

**如果卡在 `git push`**：说明第 ② 步没配好凭据，回去重做那一步。

**如果卡在「创建 Release 失败」**：多半是 token 权限不够（回第 ① 步重新生成，勾上 `projects`），或者 token 里有空格/换行（重新复制一遍）。

**等 10 分钟内**，服务器计划任务会自动完成：拉清单 → 下载产物 → 换前端目录 → 换 jar → 重启后端容器 → 健康检查。

**验证部署成功**（本地 Git Bash）：

```bash
curl -s http://115.29.29.83:8080/api/health
```

**看到什么算成功**：

```json
{"code":200,"message":"成功","data":{"status":"UP","components":{"mysql":"UP","mysqlCostMs":3,"redis":"UP","redisCostMs":2}}}
```

同时浏览器打开 http://115.29.29.83:8080/ 能正常看到商城首页。

**最后一步（收尾）**：新 jar 已经上线了，`/api/health` 现在真的存在了。回到宝塔 → 文件 → 编辑 `update.conf`，把探活地址改回来：

```
HEALTH_URL=http://127.0.0.1:8074/api/health
```

保存即可，下次部署就会用上正式的探活接口。

## 以后每次发版（熟练后只有这些）

```bash
cd /e/PeopleHappy
export GITEE_TOKEN=令牌          # 同一个终端窗口里不用重复 export
bash deploy/release.sh
```

只改前端（样式、文案）时更快：

```bash
bash deploy/release.sh --skip-backend
```

然后等最多 10 分钟，看服务器日志：

```bash
# 本地 Git Bash 里看不了服务器日志，用宝塔面板：计划任务 → 点任务 → 日志
```

## 出问题了怎么查

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 计划任务日志：拉取版本清单失败 | 服务器连不上 Gitee raw | 宝塔终端执行 `curl -I https://gitee.com/liao-zhenhan/happy-mart/raw/master/deploy/manifest.txt` |
| 计划任务日志：下载失败 | Release 资产没传完，或 tag 对不上 | 打开 Gitee 仓库 → 发行版，看资产是否都在、tag 是不是 `v<版本号>` |
| 计划任务日志：sha256 不匹配 | 传输损坏 | 直接等下个 cron 周期重跑，脚本会重下 |
| 计划任务日志：前端切换失败 / 产物结构不对 | zip 顶层多套了一层 `dist/` | 贴日志给我 |
| 计划任务日志：健康检查超时 | 新 jar 起不来 | 宝塔终端 `cd /www/wwwroot/happy-mart && docker compose logs --tail=100 backend` |
| 部署成功了但页面还是旧的 | 浏览器缓存 | `Ctrl+F5` 强刷（`favicon.svg`、`icons.svg` 不带 hash 且缓存 30 天） |
| Gitee 上看不到 Release | token 权限或网络问题 | 贴 `release.sh` 的报错 |
